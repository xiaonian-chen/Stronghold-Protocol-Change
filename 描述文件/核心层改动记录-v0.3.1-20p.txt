七、克莱门莎（clementia）角色扩展 mod — 核心层改动
================================================================================

clementia 是第一个"角色类" mod（manifest.type = 'character'），为克莱门莎（char_4231_clemnt）
提供改版机制：新特质（全局击杀计数 → 盟约层数）+ 阿戈尔、不屈、迅捷/突袭三盟约。
通过 _flags 位掩码区分原版/改版、迅捷/突袭模式。

── 核心层改动（Stronghold-Protocol/ 中直接修改的文件）──

[28] public/js/ui/detailPanel.js — GarrisonBlock 特质文本渲染优先级
    位置：GarrisonBlock 组件
    原：<${RichText} as="p" text=${garrison.descRaw || garrison.desc} ... />
    改：<${RichText} as="p" text=${garrison.desc || garrison.descRaw} ... />
    原因：浏览器 HTTP 缓存导致 descRaw 可能为首次加载的旧值；
          desc 与 descRaw 内容一致，但 desc 随 garrison.json 更新而刷新；
          优先取 desc 避免因缓存显示过期文本（如精锐版应显示 "+2层" 却显示 "+1层"）

[29] public/js/render/app.js — 盟约叠层弹出图标位置修复
    位置：盟约层数变化时的 fx.pop 弹窗效果
    新增：let layerPopSeq = 0 自增计数器（约 L344）
    原：fx.pop(tex, `+${n}`, 0xffffff, layerPops.size)
    改：fx.pop(tex, `+${n}`, 0xffffff, ++layerPopSeq)
    原因：多个盟约首次加入后 layerPops.size 固定为 3（阿戈尔+不屈+迅捷/突袭）；
          后续任何盟约叠层时所有 pop 都使用位置索引 3，导致图标重叠；
          改用自增计数器使每次弹出使用唯一索引，图标不再重叠

── clementia mod 自有文件（mods/扩展角色/clementia/）──

[30] overrides/shared/diy.js — DIY_OP_MODS 表 + augmentDiyRecord 钩子
    - DIY_OP_MODS：per-charId 的 bonds() 和 garrisonId() 工厂函数
      _flags bit 1=迅捷(0)/突袭(1), bit 2=原版(0)/改版(1)
      bonds() 返回 []（原版）或 ['indomShip', 'swiftShip'|'raidShip']（改版）

上游 MANIFEST.json 校验要求每个文件的 size+SHA-256 与磁盘一致。

若某个 mod 的 public/ 或 overrides/ 中存在与上游同名的文件，
浏览器实际收到的文件可能与 computeVanillaContent() 读磁盘计算的不一致，
导致哈希不匹配 → "内容未通过校验" 错误。

[39] server/index.js — computeVanillaContent 调用时序修复
    - 原顺序：packs.refresh(true)（mod install）之前就调用了 computeVanillaContent
      此时 mod 尚未 loadData()，garrisons.json 等数据文件尚未被注入
      但 modServer.js 的 tryServeModFile 已拦截请求返回旧版本 → 哈希不匹配
    - 修复：将 computeVanillaContent 移到 packs.refresh(true) 之后
      （第 108 行 refresh → 第 111 行 computeVanillaContent）
    - 效果：mod 装完数据后统一计算哈希，不再出现"151651 bytes, not 151879"等错误

[40] mods/扩展角色/clementia/public/data/garrisons.json — 删除

    - 问题：modServer.js 的 tryServeModFile 遍历 public/ 目录，发现该文件后
      将其返回给客户端的 GET /data/garrisons.json 请求
      由于该文件是旧版本（缺少 clementia 条目或 descRaw 过期），
      客户端收到的 garrisons.json 与 computeVanillaContent 计算的哈希不匹配
    - 修复：删除该文件。garrisons.json 由 generateClientGarrisonData()
      直接写入 Stronghold-Protocol/data/ 目录，不经过 mod 拦截

[41] Stronghold-Protocol/plugins/plugin-dup-strategies/ — 删除

    - 每次启动时打印 "[plugins] plugin-dup-strategies …" 无意义日志

十二、赤刃明霄陈强制限伤（char_1050_chen3 hard-coded limit）— 2026-10-24
================================================================================

不管房间 bossHitLimit 开关状态如何，赤刃明霄陈（char_1050_chen3）始终受 30 万
首领单次受伤上限限制。其他干员完全跟随开关行为。

── 设计背景 ──
  赤刃明霄陈的技能 3 在极高盟约层数（999炎、999奥术等）下可能对首领造成过高的
  单次伤害。对其施加永久限伤可避免她过度影响首领战体验，同时不影响其他干员。

── 实现逻辑 ──

  [50] mods/20p/overrides/server/sim/damage.js — leaderHitCancelled 改造
      a) 函数签名新增 source 参数（攻击者单位）：
         export function leaderHitCancelled(battle, target, amount, source)

      b) 开关关闭时的判断改写为"非陈则跳过限伤"：
         if (battle.flags && battle.flags.bossHitLimit === false) {
           if (!source || !source.def || source.def.charId !== 'char_1050_chen3')
             return false;
           // 赤刃明霄陈：不跳过，继续走下方 BOSS_HIT_LIMIT 常规限伤逻辑
         }

      c) 调用处传入 source（第 383 行）：
         原：if (final > 0 && leaderHitCancelled(battle, target, final)) return 0;
         改：if (final > 0 && leaderHitCancelled(battle, target, final, source)) return 0;

── 四种场景行为矩阵 ──

  开关 \ 攻击者  │ 其他干员        │ 赤刃明霄陈
  ───────────────┼─────────────────┼─────────────────
  开启（默认）   │ 正常限伤        │ 正常限伤
  关闭           │ 不限伤（放行）  │ 强制限伤 ✅

── 注意 ──
  - 仅影响首领战/隐藏核心中对领导者（isBoss）的 hit
  - 普通战斗中的伤害数字不受此逻辑影响
  - 无来源伤害（元素爆发等）source 可能为 null，走"非陈"分支放行
  - 其他 operator 如需同样处理，加一行 charId 判断即可
